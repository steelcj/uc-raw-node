## Progress

### Phase 1: The aborted state

Done.

- `raw_node_transport_incus_exec` sets `raw_node_transport_state`: `none` in its first task (before the input checks), `adopted` in the task that accepts an existing instance, `created` in the task just before `incus launch`. `raw_node_incus_launched` and `raw_node_incus_adopted` are set in those same three tasks, so they cannot disagree with it.
- `handle_failure.yml` copies the state (undefined counts as `none`) while capturing the failure, chooses the action from it, and writes it to the failure record as `action`: `abort` (state `aborted`, no teardown, no alert), `quarantine` for `adopted` (state `quarantined`, alert, no teardown call), or for `created` the existing path: `destroy` if `can_destroy`, else `quarantine`. Secrets are still deleted and the run still ends with the original failure.
- `set_attempt_state.yml` accepts `aborted`. The `build.yml` comment block now says failure handling "aborts (nothing was created), destroys or quarantines".
- The transport README describes the fact and its three values, and the teardown table now says an adopted instance's teardown is not called in a build run.

Checks: `tests/build_scenarios.yml` (stand-in) passes six scenarios: `success` confirmed; `payload_failure` destroyed, no alert; `teardown_failure` quarantined; `placeholders` now `aborted` with `action: abort`, no alert, nothing launched; new `refused_existing` (unmarked instance launched first) `aborted`, instance still there without the marker; new `adopted_failure` (unmarked instance, `-e raw_node_incus_allow_existing=true`, failing payload) `quarantined` with the adopted-instance alert and no `teardown_error`, instance still there without the marker. The runner deletes the leftover instances by hand. The rest of the suite (`validate.yml`, `tests/prepare_paths.yml`, `tests/transport_incus_exec.yml`, `tests/destroy_scenarios.yml`) and every syntax check pass.
