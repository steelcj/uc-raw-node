### Phase 1: The aborted state

Done.

- `raw_node_transport_incus_exec` sets `raw_node_transport_state`: `none` in its first task (before the input checks), `adopted` in the task that accepts an existing instance, `created` in the task just before `incus launch`. `raw_node_incus_launched` and `raw_node_incus_adopted` are set in those same three tasks, so they cannot disagree with it.
- `handle_failure.yml` copies the state (undefined counts as `none`) while capturing the failure, chooses the action from it, and writes it to the failure record as `action`: `abort` (state `aborted`, no teardown, no alert), `quarantine` for `adopted` (state `quarantined`, alert, no teardown call), or for `created` the existing path: `destroy` if `can_destroy`, else `quarantine`. Secrets are still deleted and the run still ends with the original failure.
- `set_attempt_state.yml` accepts `aborted`. The `build.yml` comment block now says failure handling "aborts (nothing was created), destroys or quarantines".
- The transport README describes the fact and its three values, and the teardown table now says an adopted instance's teardown is not called in a build run.

Checks: `tests/build_scenarios.yml` (stand-in) passes six scenarios: `success` confirmed; `payload_failure` destroyed, no alert; `teardown_failure` quarantined; `placeholders` now `aborted` with `action: abort`, no alert, nothing launched; new `refused_existing` (unmarked instance launched first) `aborted`, instance still there without the marker; new `adopted_failure` (unmarked instance, `-e raw_node_incus_allow_existing=true`, failing payload) `quarantined` with the adopted-instance alert and no `teardown_error`, instance still there without the marker. The runner deletes the leftover instances by hand. The rest of the suite (`validate.yml`, `tests/prepare_paths.yml`, `tests/transport_incus_exec.yml`, `tests/destroy_scenarios.yml`) and every syntax check pass.

### Phase 2: Attempt history

Done.

- `write_attempt.yml` reads the current `attempt.yml`, if any, and refuses before moving anything unless the state is `aborted` or `destroyed` (or there is no record) or `-e raw_node_attempt_replace=true` is given. A record whose state is missing or unknown is refused too, which is the safe reading of the default. The message names the state and gives both ways forward.
- Otherwise it names the history folder from the earlier attempt's `started`, then `updated`, then the time of the move, rewritten from `2026-11-21T16:41:18Z` to `2026-11-21--16-41-18` (still UTC, as the records hold it, where the sessions convention uses local time), adds `-2`, `-3` and so on if the name is taken, copies whichever of `attempt.yml`, `failure.yml` and `confirmation.yml` exist into it, then overwrites `attempt.yml` with the new record, then removes the earlier `failure.yml` and `confirmation.yml`. Overwriting `attempt.yml` instead of removing it means the current folder never lacks an `attempt.yml`, which is stricter than the kickoff's "copy first, then remove the originals". A run that dies after the overwrite and before the removal leaves an old confirmation beside a new `in_progress` record, which the confirmation rule makes harmless.
- New variables: `raw_node_attempt_dir`, `raw_node_attempt_current_stats`, `raw_node_attempt_previous`, `raw_node_attempt_history_found`, `raw_node_attempt_history_dir`, all in the `raw_node_attempt_*` row. `raw_node_attempt_replace` is an operator input that no step sets.
- README operational notes now say that `confirmation.yml` counts only while `attempt.yml` says `confirmed`, and describe the history folders and `raw_node_attempt_replace`.
- The three scenario runners now refuse to run against real Incus (`raw_node_test_stand_in=false`) without a dedicated project, since their project defaults to `default`. Not asked for by the kickoff; it closes a way for a test to launch and delete in the default project.

Found while writing it: inside a Jinja statement, a string literal such as `'\1'` is unescaped before the filter sees it, so `regex_replace` backreferences there must be written `'\\1'`. The first run named every folder `--------`.

Checks: new runner `tests/attempt_history.yml`, which builds through `tests/build.yml` (and once through `tests/destroy.yml`) as separate runs, passes all six cases: aborted then rebuilt (the first attempt's `attempt.yml` and `failure.yml` in one folder named from its `started`, content unchanged); confirmed then rebuilt (refused, message names `confirmed` and `raw_node_attempt_replace=true`, `attempt.yml` and `confirmation.yml` checksums unchanged, no `history/`); the same with replace after removing the node (confirmed again, the earlier `attempt.yml` and `confirmation.yml` in history); a standalone destroy's record without `started` (folder named from `updated`); two records that started in the same second (`2026-01-02--03-04-05` and `2026-01-02--03-04-05-2`); a record left `in_progress` (refused, record unchanged, no `history/`). Full stand-in suite and syntax checks pass.

### Phase 3: Report timeout as a parameter

Done.

- `wait_phone_home.yml` passes `raw_node_transport_address_timeout: "{{ raw_node_report_timeout }}"` with `vars:` on its `include_role`. The Incus role's `address.yml` computes `raw_node_incus_address_wait` from `raw_node_transport_address_timeout`, falling back to the role's `raw_node_incus_address_timeout`, whose default is now `{{ raw_node_incus_wait_timeout }}`. `main.yml`'s own wait before the payload passes `raw_node_transport_address_timeout: "{{ raw_node_incus_wait_timeout }}"` on its `include_tasks`, so it keeps using `raw_node_incus_wait_timeout`. `waited` in `raw_node_transport_address` reports the value used. The `no_report` message still names `raw_node_report_timeout`'s value.
- No task or default under `roles/` reads `raw_node_report_timeout` any more; the only mention left is the transport README's description of what the controller passes.
- The stand-in client now drops an instance's global address once its payload has run, when `artifacts/fake-incus.json.drop-address` exists. With it, a new `no_report` scenario (stand-in only) tests the path the migration could not.

Checks: `tests/build.yml -e raw_node_test_scenario=no_report -e raw_node_report_timeout=7` with the stand-in client failed as expected in 23.7 s. The report-time address wait ran with 2 retries (`ceil(7 / 5)`), where the transport's own 120 s fallback would have given 24, which shows the transport used the 7 seconds passed to it. The failure record has `failed_task: Fail on missing report`, `reason: no_report`, `detail: no address report for rn-test-incus-exec from the incus_exec transport within 7 seconds`, `clause: 'none checked: no report was received'` and `action: destroy`; the attempt ended `destroyed`. The `no_report` scenario in `tests/build_scenarios.yml` checks the same and that the whole run takes under a minute. All seven build scenarios, the rest of the suite (including `tests/attempt_history.yml`) and every syntax check pass.
