### Phase 2: Paths, secrets checks and the attempt record

Done. Added `tasks/prepare_paths.yml`, `tasks/write_attempt.yml`, `tasks/set_attempt_state.yml`, and the test `tests/prepare_paths.yml` with its per-case task file `tests/tasks/prepare_paths_case.yml`.

- `prepare_paths.yml` sets `raw_node_records_dir`, `raw_node_reports_dir`, `raw_node_logs_dir` and `raw_node_secrets_dir`. Each path is expanded with `expanduser` and joined onto `raw_node_root` with `path_join`, so an absolute path is kept as it is and a relative one (`-e raw_node_secrets_path=./secrets`) is taken from the repository root rather than from wherever the module happens to run.
- The repository check runs exactly as written: `git rev-parse --show-toplevel` in `raw_node_root`, both sides through `realpath`, a prefix comparison, then `git check-ignore -q <real path>/.probe` only for a path inside. For the secrets path, 0 continues and anything else stops, with different messages for 1 and for other codes. For records, reports and logs, the same outcomes give a warning. Without a git checkout (or without git), every path counts as outside, with a note.
- All checks run before anything is created. Then `<path>/<hostname>/` is created for records, reports and logs (mode 0700), and every missing directory from `/` down to `<secrets path>/<hostname>` is created one level at a time with mode 0700, so only missing directories are created and existing parents are not touched. The permission check covers the secrets path and the node's directory where they exist: each must be a directory with no group or other bits.

### Phase 3: The transport

Done. Changed `raw_node_transport_incus_exec`: `tasks/main.yml` rewritten, `tasks/address.yml` added, `tasks/destroy.yml` rewritten, `defaults/main.yml` reviewed, `vars/main.yml` added, `README.md` rewritten. Extended `tests/bin/incus` and rewrote `tests/transport_incus_exec.yml`.

- **Paths.** The payload is read from `{{ raw_node_secrets_dir }}/{{ raw_node_hostname }}/raw-node-firstboot` and the run log written to `{{ raw_node_logs_dir }}/{{ raw_node_hostname }}/incus_exec-run.log` (`raw_node_incus_run_log`), mode 0600.
- **Masked tasks.** The payload stat, push, run and log write carry `no_log: true`. Push and run register with `failed_when: false`; a following block sets `raw_node_failure_reason` (step name, exit code, instance, log path, no output) and fails with it.
- **Ownership marker.** Launch sets `--config user.uc-raw-node.created=true --config user.uc-raw-node.hostname=<hostname>`. The key names live in `vars/main.yml`.
- **`destroy.yml`** needs only the hostname and project. It works in two contexts: in a build run it deletes only an instance that this run launched and that carries the marker, refuses (fails) for an adopted instance, and does nothing if this run launched nothing; standalone (`raw_node_destroy_standalone: true`, set by `destroy.yml`) it deletes any instance carrying the marker for the hostname and refuses one without it. A missing instance counts as already gone. See the known gaps section for why the in-run check had to be stronger than the one in the kickoff.
- **`address.yml`** holds the instance lookup and address expression that used to be inline in `main.yml`; `main.yml` now includes it with `raw_node_incus_address_timeout` set to `raw_node_incus_wait_timeout`. It does not fail on timeout, and sets `raw_node_transport_address` (`found`, `ipv4`, `ipv6`, `ssh_host_keys`, `waited`) for the caller to judge. It also reads `/etc/ssh/ssh_host_*_key.pub` through `incus exec`, which was straightforward; the list is empty when the image has no SSH server.
- **Precedence.** `raw_node_incus_allow_existing` moved to `vars/main.yml`. Reasoning: the operator's way to set it is `-e` for one run, and `-e` outranks role vars, so nothing an operator legitimately does is lost; what role vars block is a play-level source (`vars_files`, play vars, inventory) turning adoption on for every run by accident. Everything else stays in `defaults/main.yml`, since project, image, profiles, timeouts and the client binary are things an operator or the controller sets. `raw_node_payload_file` stays a default so a test can point it elsewhere; the build pipeline never overrides it.
- **Stand-in client.** Records `--config` keys and shows them in `list`; refuses to delete an instance without `user.uc-raw-node.created=true` (overridable with `FAKE_INCUS_ALLOW_UNMARKED_DELETE=1` for test cleanup); fails `delete` when `FAKE_INCUS_FAIL_DELETE=1` or `artifacts/fake-incus.json.fail-delete` exists; keeps its state in `artifacts/fake-incus.json` by default instead of `/tmp/fake-incus.json`; runs pushed payloads with `sh`, since the payload in the secrets path is mode 0600; prints a stand-in host key for the host key command.

Checks: `PATH="$PWD/tests/bin:$PATH" ansible-playbook -i localhost, -c local tests/transport_incus_exec.yml -e raw_node_test_destroy=true` passes. It checks the marker keys, the payload exit code, the run log (in `artifacts/logs/`, mode 0600) and that teardown removed the instance. The new second case launches `rn-test-incus-exec-foreign` without the marker and checks that the transport refuses to adopt it, that a build-run teardown leaves it alone, that a standalone teardown refuses it, and that it still exists without the marker; the test then deletes it by hand. `git status --ignored` shows nothing new outside `artifacts/`, and the stand-in state is empty afterwards. ## Departures from v0.1.8

Kept up to date as the work goes; each one is a candidate for v0.1.9.

- **Contract input as extra vars.** The design gives the command as `-e @raw-node-input.yml`, but `load_input.yml` read a file from `raw_node_input_file`, whose default was `{{ playbook_dir }}/raw-node-input.yml`, a path inside the repository. Following the design, `load_input.yml` now collects the five fields from extra vars, and reads a file only when `raw_node_input_file` is set explicitly. The default was removed, since it invited keeping contract input in the repository. Extra vars cannot be listed, so the "unknown fields" warning is only given for file input.
- **`raw_node_input_*` per field.** The design says `load_input.yml` copies each checked field into a `raw_node_input_*` variable. The existing code sets `raw_node_input` (a mapping, which is in the prefix) and `raw_node_hostname`, and both already work, so they were kept and no per-field variables were added. Nothing reads the other fields yet, since the payload is a placeholder.
- **`raw_node_strategy`.** The prefix table names `raw_node_strategy` as set by `resolve_platform.yml`; the existing name is `raw_node_delivery_strategy`, which works and was kept.
- **Output path defaults.** The design gives `{{ playbook_dir }}/records` and so on; per the known gap default they are built from `raw_node_root` instead.
- **`updated` in the attempt record.** The design lists hostname, platform key, strategy, transport, start time and state. The record also carries `updated`, the time of the last state change, which is what Phase 7 timings and an operator reading a stale `in_progress` record need.
- **Working variables in `prepare_paths.yml`.** The prefix table gives `prepare_paths.yml` only the expanded path names. Its intermediate values (repository root, resolved secrets path, ignore checks) use `raw_node_paths_*`, which the table does not list.
- **Directory modes.** The design does not give modes for the per-hostname records, reports and logs directories; they are created 0700. Records and reports are written 0644, logs and secrets 0600.
- **Transport output for the controller.** The prefix table has no name for what a transport hands back to the generic controller. `address.yml` sets `raw_node_transport_address`, next to the existing `raw_node_transport_result`, rather than an `raw_node_incus_*` name the controller would have to know.
- **`raw_node_destroy_standalone`.** A new switch, set by `destroy.yml`, so the transport's teardown can tell a build run from a standalone teardown (see the known gaps). It defaults to the safe side: an unset switch only deletes what the current run launched.
