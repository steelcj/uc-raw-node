### Phase 2: Paths, secrets checks and the attempt record

Done. Added `tasks/prepare_paths.yml`, `tasks/write_attempt.yml`, `tasks/set_attempt_state.yml`, and the test `tests/prepare_paths.yml` with its per-case task file `tests/tasks/prepare_paths_case.yml`.

- `prepare_paths.yml` sets `raw_node_records_dir`, `raw_node_reports_dir`, `raw_node_logs_dir` and `raw_node_secrets_dir`. Each path is expanded with `expanduser` and joined onto `raw_node_root` with `path_join`, so an absolute path is kept as it is and a relative one (`-e raw_node_secrets_path=./secrets`) is taken from the repository root rather than from wherever the module happens to run.
- The repository check runs exactly as written: `git rev-parse --show-toplevel` in `raw_node_root`, both sides through `realpath`, a prefix comparison, then `git check-ignore -q <real path>/.probe` only for a path inside. For the secrets path, 0 continues and anything else stops, with different messages for 1 and for other codes. For records, reports and logs, the same outcomes give a warning. Without a git checkout (or without git), every path counts as outside, with a note.
- All checks run before anything is created. Then `<path>/<hostname>/` is created for records, reports and logs (mode 0700), and every missing directory from `/` down to `<secrets path>/<hostname>` is created one level at a time with mode 0700, so only missing directories are created and existing parents are not touched. The permission check covers the secrets path and the node's directory where they exist: each must be a directory with no group or other bits.
- Every task that refers to the secrets path has `no_log: true`. Their results are judged by separate asserts without `no_log`, whose messages name the setting (`raw_node_secrets_path`) and the mode, never the path.
- `write_attempt.yml` writes `hostname`, `target_platform`, `strategy`, `transport`, `started`, `updated` and `state: in_progress`, and sets `raw_node_attempt_file`, `raw_node_attempt_started` and `raw_node_attempt_state`. `set_attempt_state.yml` reads the record from disk, sets `state` and `updated`, and writes it back; if the record is missing it writes a new one from the hostname and platform, without a start time (for `destroy.yml -e target_platform` on a host that did not build the node).

## Departures from v0.1.8

Kept up to date as the work goes; each one is a candidate for v0.1.9.

- **Contract input as extra vars.** The design gives the command as `-e @raw-node-input.yml`, but `load_input.yml` read a file from `raw_node_input_file`, whose default was `{{ playbook_dir }}/raw-node-input.yml`, a path inside the repository. Following the design, `load_input.yml` now collects the five fields from extra vars, and reads a file only when `raw_node_input_file` is set explicitly. The default was removed, since it invited keeping contract input in the repository. Extra vars cannot be listed, so the "unknown fields" warning is only given for file input.
- **`raw_node_input_*` per field.** The design says `load_input.yml` copies each checked field into a `raw_node_input_*` variable. The existing code sets `raw_node_input` (a mapping, which is in the prefix) and `raw_node_hostname`, and both already work, so they were kept and no per-field variables were added. Nothing reads the other fields yet, since the payload is a placeholder.
- **`raw_node_strategy`.** The prefix table names `raw_node_strategy` as set by `resolve_platform.yml`; the existing name is `raw_node_delivery_strategy`, which works and was kept.
- **Output path defaults.** The design gives `{{ playbook_dir }}/records` and so on; per the known gap default they are built from `raw_node_root` instead.
- **`updated` in the attempt record.** The design lists hostname, platform key, strategy, transport, start time and state. The record also carries `updated`, the time of the last state change, which is what Phase 7 timings and an operator reading a stale `in_progress` record need.
- **Working variables in `prepare_paths.yml`.** The prefix table gives `prepare_paths.yml` only the expanded path names. Its intermediate values (repository root, resolved secrets path, ignore checks) use `raw_node_paths_*`, which the table does not list.
- **Directory modes.** The design does not give modes for the per-hostname records, reports and logs directories; they are created 0700. Records and reports are written 0644, logs and secrets 0600.
